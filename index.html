03 / 标准化连接

先确定不同服务如何承接

商品推荐、物流查询、订单确认等服务很难只靠文本表达；平台需要一套成熟、可复用的结果承接方式。

业务难点

行业与任务差异大查询、浏览、确认和交易的字段、状态与操作不同
供给将持续增加逐家设计与开发会使交付成本随品牌数量线性增长
统一体验与个性逻辑并存既要符合千问规范，也要允许企业承载自身业务规则
核心问题不同复杂度的服务，应通过什么形式、如何承接？

先划清卡片、模板与 H5 的边界，再建设规模化交付方案。

调研验证对比微信开发者平台、开放平台 Skill / MCP、开源协议与小微助手方案，重点判断输出稳定性、交互复杂度与接入成本。
固定模板

复用稳定，适合结构明确的信息服务。

H5 容器

灵活但成本高，承接复杂流程与个性逻辑。

动态 A2UI

首期稳定性与治理成本暂不满足要求。

关键判断

模板承接稳定部分，H5 承接复杂流程。

这一步不是先画模板，而是先判断通过什么形式、如何承接。我补充调研了微信开发者平台、开放平台与开源 MCP 和 Skill，也结合小微助手及三方方案观察真实输出。按只读查询、轻交互、单次写入和复杂多步骤做分层后，我判断首期先用模板承接结构稳定的查询与浏览，复杂交易继续交给 H5。

关键判断

先选供给组织方式，再优化页面形态

方案比较同时看用户心智、任务启动、供给扩展与运营成本。

在数据定位后，我先把旧版线上方案和多种短期方向放到同一套界面中比较。这个过程让我意识到，广场改版不是换一种卡片样式，而是在选择供给组织逻辑，因此后续评估的重点是用户心智、任务启动、供给扩展与运营成本。

04.2 / 方向判断

方向 B

个人优先

方向 C

运营优先

我发散了场景、个人和运营三种组织方向。个人优先依赖更充分的用户信号，运营优先容易让结构随资源变化；场景优先能够直接对应用户目标，同时容纳不同品牌与快捷任务，因此最终选择方案 A。

03用户在问什么？Top Query 与需求分布

从平台视角，我补齐了三层判断

指标口径：先回答最基础的曝光、访问与需求问题。

权限边界：保证数据可解释、可授权且不泄露用户隐私。

经营闭环：把用户需求反馈给品牌，推动内容、能力与运营位持续迭代。

需求洞察→能力优化→服务分发→数据反馈
为了让生态形成持续投入，我还支持了商家数据看板。首期先回答品牌最关心的三个问题：多少人看见、多少人进入、用户在问什么。我调研多类平台的数据产品，梳理曝光和访问口径、Top Query 以及权限隐私边界。它的价值是把一次接入变成持续经营，让需求洞察反向推动能力和运营优化。

06.1 / 非共识判断

AI 能力正在原子化，但用户不该手动“搭积木”

模型、工具与真实服务会成为可被发现、授权、调用和组合的能力单元；复杂度应由个人代理吸收。
过去

能力被封装在产品入口里

用户寻找 App、学习功能，并亲自衔接多个步骤。

→
正在发生

能力边界被标准化描述

Skill、MCP、CLI、Agent 与服务协议，让机器理解输入、权限和结果。

→
下一步

个人代理按目标订阅与装载

用户定义目标与边界，AI 按需选择能力、推进任务并检查结果。

关键取舍

该做：建设能力标准、订阅与运行机制

让能力可描述、可授权、可验证、可恢复、可组合。

不该做：把协议和 Tool 选择直接交给用户

用户管理目标和规则，而不是管理底层技术栈。

微信小程序、开放接口与生态服务逐步进入 AI 调用链路
支付宝支付、交易与小程序能力持续向智能体开放
飞书等生产工具通过 MCP、CLI 与开放接口连接数据和生产流程
我的判断原子化真正改变的不是“功能更多”，而是能力能够离开固定入口，被个人代理长期订阅、按需加载、动态组合。
我认为能力原子化是一条确定趋势，但这里有一个非共识：不应该让用户自己搭 Tool。真正变化的是模型、工具和真实服务的能力边界被标准化描述，并由个人代理按目标订阅、装载和组合。微信、支付宝、飞书的开放动作都在说明能力正在离开固定入口。产品该做的是标准、授权、订阅和运行机制；不该把协议和技术选择暴露给用户。

06.2 / 非共识判断

生产权开始下放，分发权向顶层 AI 上移

能力供给越分散，越需要一个真正代表用户的个人代理，决定订阅什么、何时调用、如何评价。
PRODUCTION / 生产侧

个人获得组织与发布能力

原子能力降低了组织资源的门槛，一个人也能把不同能力组合成可交付的服务。

  • 一套旅行策划服务
  • 一套营销内容和投放流程
  • 一个可被他人复用的办公 Agent
DISTRIBUTION / 分发侧

顶层 AI 掌握能力选择权

个人代理理解长期上下文，并在已订阅与可发现的能力中做选择、组合和评价。

理解目标→管理订阅→按需装载→评价结果
交互入口的演进
人找信息→信息找人→需求找能力
关键变化需求找能力，不等于服务找人。个人代理应代表用户目标选择供给，而不是把品牌分发包装成 AI 推荐。
我的第二个判断是，原子化不一定带来去中心化。生产权会下放，个人可以组织能力并发布服务；但分发权会向顶层 AI 上移。能力越多，谁更理解用户，谁越能决定订阅什么、何时装载、如何评价。这里需要坚持用户立场：需求找能力，不是服务找人，个人代理应代表用户选择供给。

06.3 / 用户价值判断

AI 的更大价值，是扩大一个人的能力范围

能力订阅让个人 Agent 持续变强；用户不只消费能力，也开始组织能力、沉淀方法并获得回报。

STEP 03

由我创造

把成功方法沉淀为可复用资产，继续服务自己或分发给他人。

定义目标→订阅与组织能力→形成结果 / 工作流 / Agent→复用与分发→获得反馈或收益
核心增量放大个人生产力让一个人完成过去需要团队才能完成的事情

这种产业变化对用户的意义，是扩大个人能力范围。第一步是超级个人助理，按需加载能力替我办；第二步是个人数字组织，组织多个角色和服务与我做；第三步是个人生产平台，把成功方法沉淀、复用和分发。用户获益有三层：先放大个人生产力，再节省时间和协作成本，最后获得反馈、影响力或经济回报。持续获益，才会形成持续使用。
